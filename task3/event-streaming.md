## Потоковая обработка данных

Опишем архитектуру потоковой обработки данных

* Когда пользователь смотрит или кликает баннер, запрос идет в API Gateway. API Gateway пушит соответствующее сообщение в кафку. Сервис статистики читает эту кафку и вставляет в кликхаус.
* По этим событиям строятся финансовые отчеты, поэтому нам важно ничего не потерять + иметь возможность перечитать события. Поэтому кафка.
* Retention обычно 3 дня - выходные + 1 рабочий день.
* Пока можно начать с двух топиков: banner_impressions и banner_clicks. То есть показы и клики.
* Схемы могут выглядеть так:
```
banner_impressions: {
    banner_id,
    user_id,
    url,
    timestamp,
    idemp_key,
}

banner_clicks: {
    banner_id,
    user_id,
    url,
    timestamp,
    idemp_key,
}
```
* В будущем схемы banner_impressions и banner_clicks могут сильно отличаться. Поэтому топики лучше сразу разделить и использовать JSON, тк он более гибкий.
* Для увеличения пропускной способности в будущем можно партицировать кафка топики. 
* Потребителей у этих топиков будет по одному - данные собирает сервис статистики и перекладывает в Clickhouse. Все остальные сервисы обращаются за данными в Clickhouse.
