## Выбор архитектурного стиля

Целевая архитектура должна представлять из себя микросервисы по следующим причинам:
* В компании достаточно большая команда (35 человек), среди них несколько бэкенд и фронтенд разработчиков, которые могут делиться на небольшие команды. Команды должны уметь работать независимо.
* Нужна масштабируемость, но не нужно масштабировать все сервисы. Нужно масштабировать сервисы, стоящие на критическом пути. Этого возможно достичь только за счет микросервисов.
* Важна устойчивость к отказам. Нельзя, чтобы неполадки, например, в сервисе статистики влияли на аукционы.
* В компании есть тестировщики. Тестировать независимые сервисы проще.
* Производительность выше за счет независимой работы сервисов.

Сразу не стоит переходить на микросервисы по следующим причинам:
* Нет инфраструктуры: нужна контейнеризация (Docker, Kubernetes). Для настройки нужно время.
* При масштабных переходах есть риск ошибок. Для компании важна непрерывная стабильность. Нужно плавное переключение с возможностью откатиться к старому решению. 

Думаю стоит выбрать постепенную декомпозицию. Модули внутри монолита изолированы, их должно быть относительно легко выносить в микросервис. Например, можно начать с выноса сервиса статистики - рядом развернуть новый микросервис, который будет читать кафку модуля Delivery Service.
