## Определение архитектурных драйверов

### Функциональные требования к системе после интеграции

1. AdScale показывает пользователям рекламу в интернете в виде баннера на основе поведения пользователя. Среди кандидатов на показ AdScale выбирает вариант с наибольшим весом с учётом ставки рекламодателя, релевантности и так далее.

2. AdScale также предоставляет API для интеграции с внешними партнёрами: на вход получает описания пользователей (массив векторов признаков пользователей), на выход через канал OpenRTB список победителей аукциона для каждого пользователя.

3. В AdScale есть кабинет рекламодателя. В нём рекламодатель может управлять рекламными кампаниями, формировать бюджеты и ставки, участвовать в аукционах в реальном времени. Также рекламодатель может смотреть статистику по кликам и показам. 

### Атрибуты качества и нефункциональные требования

* **Производительность** --  P95 времени отклика не менее 100 ms
* **Масштабируемость** -- через 3 месяца система должна быть способно обрабатывать до 18_000 RPS трафика, через год - 50_000 RPS
* **Доступность** - SLA 99,9%
* **Надёжность** - должна быть обеспечена непрерывность бизнеса
* **Безопасность** - не хранить персональные данные пользователя, предлагать рекламу на основе анонимизированных данных; защита платёжной информации рекламодателей
* **Изменяемость** - рекламодатели могут участвовать в аукционах в режиме реального времени и менять ставки.
* **Сопровождаемость** - понятные и удобные инструменты мониторинга, алерты и логи. Новые DSP-партнёры легко подключаются к системе.

### Ограничения

#### Технические
* Стек - C++ / Go / Python / Node (гибридный монолит)
* БД - PostgreSQL (одна инстанция)
* Нет кэшей и очередей
* Нет контейнеризации, деплой вручную
* Есть один production кластер
* Переписать с нуля нельзя, нужна постепенная миграция

### Бизнесовые
* В штате AdScale 35 человек: backend-, frontend- и DevOps-разработчики, тестировщики, дизайнеры, сотрудники службы поддержки и менеджмент. Выделенных SRE-инженера, технического писателя и бизнес-аналитика в компании нет. Бюджет ограничен, средств на найм новых сотрудников нет.
* Через 3 месяца нужно обеспечить подключение новой DSP-площадки
* Инфраструктура on-premise не даёт время на миграцию в облако
* Aинансовых штрафов от DSP-партнёра в случае деградации сервиса
