## Проектирование взаимодействие

* Для внутреннего взаимодействия лучше выбрать grpc. Размер информации о ставке небольшой. Если гонять через REST, то будет много накладных расходов на заголовки.
* Для внешнего взаимодейсвтия лучше выбрать REST. С таким API проще интегрироваться + гибкость в выборе стека.
* Так как ставки могут быстро меняться, то здесь лучше использовать синхронный подход.
* Лучше использовать Kafka,  тк это более надёжный механизм: можно перечитать сообщения заново, можно подсадить нескольких потребителей. Информация о событиях кликов и показов критична, нельзя что-то потерять - по этим данным происходят финансовые расчеты с рекламодателями и DSP.
* API Gateway нужен в виде proxy. Нужен рейт лимитинг и circuit breaker.
